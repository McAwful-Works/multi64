# Branding

The marks for the three Windows apps, and the scripts that draw them.

| File | Used by |
|------|---------|
| `multi64.svg` | Multi64, and Multi64 Test |
| `xfer64.svg` | Xfer64 |
| `ap64.svg` | AP64 |

Each is a square 1024×1024 mark in the N64's flat-shaded style: no gradients, no strokes that
depend on scale, so it stays legible at the 28px the apps draw it at.

## These files are the masters

Each app carries its own copy at `crates/<app>/src/brand-mark.svg`, because a Tauri app serves
`frontendDist` as-is and cannot reach outside it. The copies are byte-identical, and
`multi64-test-app` uses Multi64's mark rather than one of its own.

Nothing checks that they match. If you change a mark here, copy it into every app that uses it
in the same change:

```sh
cp branding/multi64.svg crates/multi64/src/brand-mark.svg
```

The installer and window icons are generated separately, by `tauri icon` from the same SVG —
see [`installer-images/README.md`](installer-images/README.md) for the NSIS sidebar and header
bitmaps, which are not generated by it.

## Drawing them

`n64style.py` renders the N64-style 3D lettering; `ap64style.py` holds AP64's own palette,
sampled from Archipelago's icon; `generate.py` drives both.

```sh
python branding/generate.py
```

The sources are kept because the marks are drawn programmatically rather than by hand: a change
means editing the geometry and re-rendering, not editing paths in the SVG.

## Using a mark in documentation

Product READMEs open with their mark beside the title. The exact markup, and the rule about
which pages get one, are in
[`docs/documentation-style.md`](../docs/documentation-style.md#8-branding).
